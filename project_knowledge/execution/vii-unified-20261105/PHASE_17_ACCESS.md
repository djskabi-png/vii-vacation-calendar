## Immutable build age

An unchanged immutable artifact no longer needs a new build merely because
its original successful build receipt is older than 24 hours. Its original
date is preserved. Actual clean HEAD, ancestor source, original tree, complete
original/current input fingerprints and the archive's SHA256 are still
rechecked. Fresh artifact audits, provisioning and runtime/public acceptance
remain separate requirements and retain their freshness limits. An invalid
or future build timestamp still fails. This changes only reusability, not
publication approval.

Independent review accepted this distinction while requiring the fresh audit
definition and checks to remain explicit. The Site archive auditor now emits
`site-archive-v1`; the upcoming aggregate gate must check the committed audit
definition rather than accept any object named an artifact audit. Source-only
reuse tests passed; complete candidate qualification and per-unit global
release integration remain in progress.
