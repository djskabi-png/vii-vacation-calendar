# Phase26: discovery snapshot acceptance

The cumulative phase25b candidate is retained unchanged. Document3 remains
deferred. This core slice prevents a page-shell success from being treated as
proof that the discovery presets are ready.

Eight server-owned semantic HTTP checks now participate in the real quality
registry, scope selection and immutable HTTP job snapshots. They cover the five
vacation periods and three current event presets. A verified empty supplier
result is valid; an unverified refreshing response is not. Vacation checks
verify period, dates, nights, guest basis, positive prices, unique positive
IDs and fresh checkedAt evidence. Event checks verify discovery version,
world, date, guest basis, accepted offers and the matching public place join.
Contact-only verified event availability can legitimately have a null price.

Vacation requests use the existing GET endpoint. Events use a single reviewed
read-only discovery POST with its complete payload constructed by the server.
There is no caller-supplied method or body facility. Unknown/mismatched semantic
IDs or routes are blocked before network access. No booking, lead, payment or
notification operation is introduced.

The canonical home date calculation was moved without changing its logic into
a pure module; existing exports remain compatible. Public offers and quality
checks now share the same Jerusalem clock, including the 14:00 cutoff. Date
expectations are frozen at check start; a rollover race can block rather than
accept a mismatched period. A later explicit run is a new operation, not an
unbounded retry of a failed immutable release subject.

The impact CLI expands the actual trusted constant definitions rather than
duplicating eight IDs. Impact ownership and required checks include the new
source and tests. The registry now has69 HTTP checks, with34 browser profiles
remaining a separate execution family.

Focused behavioral, registry, scope and impact tests:43 passed. Date/period and
readiness family:57 passed. These runs overlap and are not summed. Full draft
TypeScript passed before the optional event till hardening. The first interface
run exposed the CLI's old initializer-only assumption; its constant dependencies
were added, and the explicit pinned registry count was updated from61 to69.
The failed logs remain retained. A fresh cumulative freeze is still required.

Independent source review found no concrete method/route/body escape. Its
suggestion to validate event till when present was implemented and tested.
This review is not cloud execution, public rollout or supplier acceptance.

Operational acceptance must first establish the target generation's accepted
snapshots, then run the complete matching immutable subject. A refreshing
response fails readiness; it does not justify restoring blocking supplier work
to ordinary page loads. Existing bounded public recovery and warming remain.
No deployment, cloud write or business action occurred in this source slice.
