# תיקון מצטבר לאחר בדיקת הציבורי

הקוד כולל את תיקוני הבדיקה הקודמת שנשמרו בקומיט 8ce2e33 ואת התיקונים הבאים. זהו תיעוד מועמד, לא אישור שכל התיקונים כבר בציבורי.

- מנגנון גלובלי עיכב בקשות API עד window.load ועוד800ms, ולכן תמונות איטיות עיכבו גם נתונים. כעת השחרור אחרי DOMContentLoaded ושתי מסגרות ציור, עם גבול100ms למסגרות ברקע. ארבע בדיקות מריצות את הסקריפט האמיתי.
- מגבלת הזמן לבקשת גילוי כוללת גם קריאת גוףJSON. חזרה מוגבלת נשמרת ל־GET בלבד, ללא הפעלה חוזרת שלPOST.
- מעבר דף שלא הושלם מקבל שחזור מוגבל באמצעות GET רגיל, אחרי8שניות ובתדירות מרבית אחת לדקה. אין שמירת כתובות חיפוש או שחזור פעולות שרת. התחלת ניווט מזוהה גם דרך instrumentation הרשמי.
- שינוי רוחב מסך סוגר את עורך החיפוש ושומר הרכב שטרם נשלח. ביטול מפורש ממשיך לשחזר את החיפוש הקודם.
- סיכום חיפוש מסלולים ואטרקציות מציג את האזור שנבחר, כולל נתיב נושא ופרמטרים.
- במרכז הקידום כל מקור מסתיים עצמאית, כולל timeout לגוף התשובה וביטול. אין הצגת ספירות לפני אימותoverview. תשובת403 מבטלת את דור הבקשות ומנקה נתונים. שלוש בדיקות מריצות את callback האמיתי עם תשובות מתחרות ומאוחרות.

סקירה עצמאית אישרה את תיקוני שערAPI, deadline וביטול ללא הרחבת הרשאות או replay. הסיבה המדויקת להקצאת הזיכרון שגרמה לשגיאתWorker עדיין אינה מוכחת; צמצום היבואים ושיפור התזמון אינם ראיה שהשגיאה נעלמה בציבורי.
